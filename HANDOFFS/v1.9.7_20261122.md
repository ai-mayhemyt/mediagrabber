1. What Happened

During an attempt to patch a Jinja template syntax error in web/app.py using sed, the template block became fatally corrupted (unclosed {% if %} tags and duplicated <select> lists). The app threw a 500 error on /login.

An attempt was made to restore a local backup (app.py.bak.v1.9.7), which reverted the code to a version before the API Tokens feature was implemented.

2. How It Was Fixed

1. Git Permission Correction: The working directory files were owned by root, preventing git from operating as the christopher user. This was fixed with sudo chown -R christopher:christopher /opt/mediagrabber.
2. Git Checkout: The broken local app.py was discarded, and the repo was force-reset to match the origin/v2.0 branch (git reset --hard HEAD), bringing back the API Tokens code.
3. Database Migration: The live users.db had already created the api_tokens table during a previous launch, but the database backups (users.db.bak.v1.9.7 and .good.20261119) were from before this table existed. The live DB is currently empty of tokens, but the schema is ready.

5. Rules for Future Development

· NEVER use sed -i to edit web/app.py. sed destroys Jinja syntax, HTML tags, and Python indentation. Use nano, vim, or Python script replacements.
· Git is the source of truth. Make changes locally, test them, and commit. If you break app.py, run git checkout web/app.py to instantly restore the last committed version.
· Permissions: Always ensure /opt/mediagrabber is owned by christopher:christopher. If you edit files with sudo, you will break git for the next time.

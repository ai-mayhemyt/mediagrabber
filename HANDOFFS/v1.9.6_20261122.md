# MediaGrabber v1.9.6 Handoff — 2026-11-22

## Shipped in v1.9.6

- **Scheduler Hotfix** — `_scheduler_loop` and `grab()`'s `run()` were crashing with "Working outside of application context" and `NoneType`.
  - Wrapped `run()` in a `_run_with_ctx()` helper that establishes `with app.app_context():` before spawning the thread.
  - Added `time.sleep(5)` startup delay in the scheduler loop.
  - Added `traceback.print_exc()` and a `status='failed'` DB update on exception to prevent infinite retry loops.
  - Added success logging: `[scheduler] fired job <id>`.
- **Version Bump** — Backend and UI strings unified to `v1.9.6`.

## Already Shipped in v1.9.5 (parallel session)

- Mobile UI fixes (`< 500px` media query).
- Version Manager `api/version/info` endpoint (uses `git ls-remote` + 5-minute cache).
- Scheduled Downloads backend and DB schema.
- Custom theme (deep purple / mint) applied as default CSS.

## Known Quirks

- `subscribePush()` is duplicated (lines 5344 and 5417 in earlier versions). Do not delete; replace `alert()` with `console.log()` in place.
- VAPID keys are hardcoded (low risk, self-hosted via Tailscale).
- `_run_with_ctx` only wraps the `threading.Thread` for `run()`. If new thread starts are added inside `grab()`, they will need the same wrapper.
